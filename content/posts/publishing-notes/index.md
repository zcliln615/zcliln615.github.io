title: "这个博客如何发布文章"
date: "2026-10-08"
---

这个博客使用 **Hugo** 生成静态页面，再通过 **GitHub Actions** 发布到 **GitHub Pages**。文章、图片与站点配置保存在同一个公开仓库中，写作不需要登录网页后台。

## 一篇文章对应一个目录

文章放在 `content/posts/<slug>/index.md` 中。`slug` 是自己确定的小写英文目录名，可以包含数字和连字符，例如 `camera-calibration`。

```text
content/
  posts/
    camera-calibration/
      index.md
```

目录名决定文章地址。修改标题或正文时不必改目录名，原有链接也就不需要跟着变化。

## 写好标题、日期和正文

文件顶部使用 YAML front matter，正文使用 Markdown：

```yaml
---
title: "相机标定学习笔记"
date: "2026-10-08"
---
```

标题和日期都需要提供。日期使用 `YYYY-MM-DD` 格式，用于首页排序与页面显示，不是定时发布指令。

正文可以使用标题、段落、列表、链接和代码块。例如，站内链接可以写成 `[关于](/about/)`，由 Hugo 解析实际访问地址，不需要在每篇文章中填写 GitHub 仓库前缀。

## 先在本地预览

使用 Hugo `0.167.0` 标准版，在项目目录启动预览：

```sh
hugo server
```

这里假定 `hugo` 已加入命令搜索路径；也可以用 Hugo 可执行文件的完整路径替代它。打开终端显示的本地网址，检查文章、导航和代码块，再提交内容。

## 推送后自动发布

把内容提交并推送到 `main` 分支后，GitHub Actions 构建站点，并把 `public/` 中的生成结果发布到 GitHub Pages。

![文章以 Markdown 编写，提交后由 Hugo 构建并发布到 GitHub Pages](publishing-flow.svg)

构建和部署是不同环节：构建成功后，还需要查看部署结果，并打开公开网址确认页面内容。生成的 `public/` 目录不需要手工提交。

源码仓库：[zcliln615.github.io](https://github.com/zcliln615/zcliln615.github.io)。

## 图片与正文一起提交

把图片放在文章的 `index.md` 旁边，或该文章目录下的子目录中，再在 Markdown 中使用相对路径。例如，本文的流程图写作：

```markdown
![发布流程](publishing-flow.svg)
```

提交时同时包含正文和图片文件，注意引用名称的大小写。Hugo 会把文章资源发布到对应文章路径下，不需要把图片单独上传到网页后台，也不需要填写仓库前缀。

## 公开内容的边界

这是公开仓库，源码和提交历史都可以被访问。不要把密码、访问令牌、私密草稿或不准备公开的个人资料放入其中；本地删除文件并不等于删除已经公开的提交历史。
